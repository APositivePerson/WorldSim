# 人物进度整合（2026-10-22）

人物相关源码、程序模型、编辑脚本、参考动作、独立调试界面及测试现已全部纳入本仓库 `character/`。银行与人物作为同一项目共同维护，构建和运行不再读取相邻目录。Agent、ASR、TTS、工作人员与银行流程保持原协议。

## 已接入

| 同门组件 | 银行中的用途 |
|---|---|
| MuJoCoEngine、HumanRenderer、SkinnedHuman、DeformationRig | 最新关节模型、皮肤、辅助骨、眨眼和面部参数 |
| MuscleController | 与同门一致的默认位置电机模式；明确关闭肌肉与被动肌腱，避免两套驱动叠加 |
| ReachTask | `take`、`hand_over` 改为实际手掌 IK；默认目标绕人物朝向旋转；误差 < 0.025 m 才能完成 |
| Anatomy.handPose / relaxedHands | 自然手掌姿态、独立手指控制 |
| WholeBodyCoordinator / CMU 07_01 | 跟随银行步态相位的摆臂与躯干协调，可关闭；动作任务优先控制其关节 |
| LocomotionSensors | 脚及子骨骼接触、支撑力、压力中心、质心速度等；站稳判定使用实际支撑力 |
| 本地 Eric 扫描人物 | 仅本地按指定 GLB 提供，缺失回退程序人物，页面可切换 |

`wave`、`nod`、`shake_head` 在接入层组合分段姿态，并等待各段物理稳定后执行下一段。它们不再分别等价于单次抬手、低头或左转头。

## 调用与反馈

浏览器大脑桥优先调用 `window.human.performAction({id, action, target})`，由 `getState().actionResult` 返回同一命令 ID 的 `running / completed / failed / interrupted`。新动作替换旧动作、超时或结束连接时取消实际任务。接受命令不代表完成。

旧的 `executeAction({action, duration, target?: [x,y,z]})` 仍保留，支持同门的预设姿态及 `reach_left/right`；新增 `setFinger(side,finger,curl)`、`setFace(patch)`、`setMotionReference(0..1)`。`getState()` 增加 reach、muscles、body、face、avatar 和 actionResult。

语音仍按工作人员 TTS → 播完 → 人物 ASR → Agent → 顾客 TTS 的原有流程运行。Web Audio 读取顾客播放音频的 RMS 音量，通过 `setSpeechLevel()` 驱动下颌；暂停、跳过、结束和机器人发言时归零。没有麦克风输入，也没有音素级口型。

## 保留的边界

- 同门的新版 LocomotionController / BalanceController 面向直行，尚不覆盖银行的转向和目标朝向。因此银行仍用原有 Locomotion / Balance / LegIK；不同时启动两套腿部控制器。
- 未启用肌肉兴奋度/疲劳实验模式。初始化使用同门默认的电机驱动模式。
- GraspTask / CupScene 针对专用抓杯实验，银行没有相应杯子物体和支撑台，未向 Agent 声明抓杯能力。递证件、接纸张和按按钮仍无物体接触闭环。
- `look_at` 仍保留 robot/help_desk 的固定左右转头映射。
- LowLevelApi.ts 仍是讨论稿，本次没有把它宣称为已实现接口。

## 后续同步方式

双方直接在同一仓库开发：人物相关改动进入 `character/`，Agent 与银行接入改动进入根目录对应模块，通过分支和 PR 合并。拉取后执行根目录 `npm ci`，再运行 `python body_3d.py`。构建脚本对仓库内源码、根锁文件、WASM、模型资产计算指纹；变化或输出缺失/损坏时重建。

默认资产来自 `character/public/models`；`--human-dist` 可以指定另一个含 models 的目录。可选扫描人物默认放在本仓库被忽略的 `character/artifacts/scanned-private/runtime/`，私有 FBX、贴图源文件与派生素材不会复制进构建。

CMU 参考来源、处理和使用条款保留在 `character/assets/motions/cmu/README.md` 与 `character/public/motions/NOTICE.txt`；该参考不是程序皮肤的 CC0 资产。

- TypeScript 检查通过；8 项动作反馈测试、9 项 Python 回归通过；576 条带停车偏差的导航路径通过。
- 真实 MuJoCo 的挥手、点头、摇头、伸手、手指控制和取消通过；实际转身 180° 后伸手误差约 2.02 厘米，确认 CMU 上身参考实际参与关节驱动。
- 真实浏览器的动作反馈、自动对话消息流程、音频轮流播放、暂停恢复、导航、扫描人物切换及音量驱动嘴部通过。语音测试使用合成音频，模型回复使用测试桩，未调用真实 GLM / 在线 TTS / ASR 服务。
- 完整真实物理路线通过：入口 → 咨询台 → 取号机 → 等候叫号 → 1 号柜台。各目的地位置误差约为 0.60、0.53、2.03、3.16 厘米，骨盆最低高度约 0.922 米；检查了关节限位、双脚离地、无根部坐标/速度改写和无辅助外力。
- 接入后的站姿可能相对 IK 内部参考偏移数厘米，旧的 2.5 厘米内部限制会在已站稳的柜台位置阻塞完成。现统一为导航的 8 厘米位置容差，同时保留实际目标距离、朝向、速度、双脚承重及持续稳定判定。
- 并发启动时构建互斥、未变化时缓存复用均通过。扫描文件未复制进构建目录；切换皮肤后仍隐藏银行碰撞盒。
