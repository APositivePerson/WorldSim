## Agent 动作反馈与失败恢复

2026-10-23：已加入 GLM-4.6V 手动视觉检查，并新增可选视觉辅助决策。人物视角观察随关键事件进入 Agent，过滤过期和错命令结果，视觉失败回退原流程。真实视觉 API 完成全景、纯背景、抬手前后 3 个样例；闭环协议与恢复逻辑使用模拟视觉/模型/身体反馈验证，尚未验证真实双模型整条银行路线，详情见 [视觉验证](视觉验证.md)。

- 服务端增加会话内命令记录，核对反馈 ID、动作和终态，拒绝重复、冲突及未知结果；最多保留 128 条命令，最近 16 条进入决策观察。
- 网页动作事件附带 command_id，过滤重复及过期关联事件；保留语音结束后触发决策的顺序。
- 本轮失败后模型原样重试最近失败动作时，改为等待并求助；允许更换动作或目标，后续外部事件可重新评估。
- 实测：14 项 Python 测试、8 项动作调度测试、浏览器流程测试通过。模拟人物行走超时，经过真实会话和决策代码、模拟模型输出，验证重复走向柜台被改为等待求助。未调用真实 GLM、ASR 或 TTS。
- 本阶段不实现 LowLevelApi 和人物技能序列，仍由人物侧接入。方法库未发现直接匹配方案，未引入经验库或自动程序改进机制。

## 背景

导师和公司合作，公司做了服务机器人的仿真场景（目前只有机器人）。导师要加入"仿真人类顾客"，
用旁观者视角观察机器人的服务。机器人不只卖给银行，所以系统要能换场景。

- 我：负责顾客 Agent（大脑），以及**大脑和小脑的接口、技能调度**
- 同门：负责人物模型和**底层关节控制**（MuJoCo WASM 版，现已纳入本仓库 `character/`，不再依赖相邻项目）
- 暂时不接公司的仿真环境

## 系统分层

```
大脑（GLM，本仓库）           做什么：说什么话、走到哪、递东西
   │ 接口①：WebSocket 动作指令（docs/接口文档.md）
小脑（技能调度，我）           按什么顺序做：路径规划、拆成技能、判断完成
   │ 接口②：技能调用（docs/小脑接口.md、docs/LowLevelApi.ts，讨论稿）
底层关节控制（同门）           关节怎么动：步态、平衡、上身姿态
```

场景信息（地点、员工、规则、人设）放在 `scenarios/<场景>/`，不写在代码里。

## 技术选型及原因

| 部分 | 选择 | 原因 |
|---|---|---|
| LLM | 智谱 GLM-5.3，`reasoning_effort=low`，60 秒超时 | 官方要求必须开思考；超时避免整场无声卡住 |
| 决策框架 | 自己写，每轮一次 LLM 调用 | 要实时响应；Deep Agents 更适合以后的离线批量生成/评估 |
| TTS | Edge-TTS（在线、免费） | 没有显卡；报 403 时 `pip install -U edge-tts` |
| ASR | SenseVoice-Small int8 + sherpa-onnx（本地 CPU） | 没有显卡，识别一句约 0.1 秒 |
| 2D 环境 | pygame-ce | Python 3.13 上比原版 pygame 稳 |
| 3D 环境 | 同门的 MuJoCo WASM 人物 + Three.js，浏览器里跑 | 不需要显卡；真实物理行走 |
| 大脑/身体通信 | WebSocket + JSON；身体在 hello 里声明能力 | 换身体、换场景时大脑不用改 |
| 语音测试 | 打字 → 员工 TTS → 顾客 ASR | 工位上不方便对着麦克风说话 |

## 调研结论

- **智元 Genie Sim 3.0**（2026-01 开源）：基于 Isaac Sim 5.1，素材多（零售/餐饮/办公/家居），但没有银行等服务场景、
  没有人（"人形"指机器人），机器人是智元 G2（干活用，不会接待），最低要 RTX 4080 16GB。
  Isaac Sim 自带的人物模块（Replicator Agent）支持 `GoTo x y z 朝向`，和小脑接口的坐标设计一致，以后可以作为第二种身体接入。

## 使用中发现的问题

- 输入 `/sys` 是旁白，不走语音；机器人说话要直接打字
- pygame 默认不显示中文输入法候选词，已设置 `SDL_IME_SHOW_UI=1`
- 3D 行走很慢（每步约 4 秒仿真时间），演示时开 8 倍速

## 2026-10-23：改为局部感知与动态绕行

- 替换上述登记路障的停步方案。导航不再接收障碍位置表，只接收前方有限范围的第一表面距离采样，积累局部占用格；站稳后重新规划并执行绕行。
- 路障随机横向偏移。移除按钮只改变环境，不通知导航恢复；默认关闭 VLM，界面明确标注局部距离感知来源。
- 无路时继续观察、限时等待；持续失败上报现有 Agent 动作失败链路。重规划有次数限制，不能把规划成功当作动作完成。
- 调试中发现部分视野和步态摆动会引起反复规划，已调整转向期触发条件，并给规划路径增加相对停步检查的额外余量。
- 浏览器完整测试已通过：路障保留、0 次视觉 API 调用、2 次重规划，最终距咨询台目标约 0.015 米。传感器单元测试覆盖视野、遮挡、移除后清除、途中新增和完全堵路；原对话流程、18 个 Python 测试、11 个动作测试及类型检查通过。
- 两个不同横向位置（-0.25、0.25 米）的真实 MuJoCo 绕行均通过，不移除障碍，各重规划 2 次并稳定到达，耗时约 689、625 仿真秒。
- 实现只覆盖躯干高度箱体距离感知；不宣称 VLM 学会绕障，也不宣称覆盖任意物体或所有银行路线。具体边界及测试命令见[局部感知导航](局部感知导航.md)。
