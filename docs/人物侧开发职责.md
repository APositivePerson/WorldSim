# 人物侧开发职责与接入要求

人物侧负责在当前 bank_customer_sim 仓库实现人物控制接口 v1，并完成相应的银行系统接入。当前规范已制定，接口改造仍待实现和验收。

相关文档：

1. docs/小脑接口.md：行为规范。
2. docs/LowLevelApi.ts：接口类型，与行为规范共同构成契约。
3. docs/接口文档.md：必须兼容的 Agent WebSocket 协议。
4. docs/人物进度整合.md 和 docs/协作开发.md：现有能力、限制和模块边界。

目标：人物独立页面和完整银行系统使用同一套可复用人物技能实现；Agent 能发起动作并得到真实的完成、失败或打断结果。

## 实现顺序

1. 检查现有 character/ 与 scene/physics/ 实现，优先复用。特别注意银行控制支持转向，人物原步态主要用于直行，不能直接替换导致银行路线退化。
2. 将 docs/LowLevelApi.ts 的类型移入 character/src/ 下的公共接口模块，并让 docs/LowLevelApi.ts 重导出，避免长期维护两份类型。人物实现和场景调用必须引用该公共类型，纳入 typecheck。
3. 实现规范要求的技能、参数校验、全身串行调度、状态记录、取消、超时和能力声明。不要为第一版额外实现多通道并发或新增 LLM。
4. 人物调试页复用该实现，保留原按钮和已有抓杯、外观等功能。不能让旧按钮绕过新调度器并覆盖正在执行的任务；显式拒绝或通过统一取消/接管机制处理。
5. 更新银行适配层及 Navigator，将原命令映射到技能，保留 window.human 兼容入口、原始命令 ID、导航和语音反馈。不得让新旧腿部控制器同时写控制量。
6. 补充有实际意义的契约测试和真实物理验证，再运行现有相关回归。

## 修改范围

人物侧主要维护 character/，并负责接口接入所需的 scene/physics/、scene/main.ts、web/actions.mjs 及相关测试调整。Agent 决策、语音与场景业务由 Agent 侧维护；涉及这些部分的变更需同步接入影响。保持 docs/接口文档.md 中 WebSocket 消息兼容。不提交个人 .env、私人扫描资产、node_modules 或构建产物。

## 验收

- 必须技能完整实现；可选能力未实现就不声明，不能用固定转头冒充三维注视。
- 拒绝新命令不影响旧任务；替换、取消、重复 ID、暂停、超时、跌倒、终态保留与回调符合规范。
- 在真实 MuJoCo 物理中验证走路转向、手势回正和目标伸手；禁止瞬移和伪造完成。
- 人物独立页能运行，银行完整路线可完成；取消导航后不得继续走向旧目标。
- 银行动作结果对应原命令 ID，语音驱动嘴部与动作调度互不覆盖。

在仓库根目录运行适用检查，记录实际结果：

```powershell
npm.cmd run typecheck
npm.cmd run test:actions
npm.cmd run test:character
npm.cmd run test:integration
npm.cmd run test:route
npm.cmd run test:browser
```

新增的契约测试必须加入常规测试入口。涉及 Python 时再运行 Python 测试。外部服务或资产缺失要说明，不把未执行的测试写成通过；模拟语音测试不能称为真实 GLM/ASR/TTS 联调。

## 遇到问题的处理规则

内部实现、适配和测试问题直接修复。接口存在可证明的问题时，优先向后兼容；确需修改签名或含义，先查清全部引用，同步类型、实现、调用方、文档、测试和版本，并写明原因。不要只改人物端接口导致银行端失效。

提交说明应记录修改模块、支持的技能、测试结果和未实现的能力。只有通过验收的能力才能标记为已实现。
