# 详细使用说明

用 LLM（智谱 GLM）驱动一个"仿真顾客"，在服务场景里和服务机器人、其他工作人员用语音交流、行动，
用来测试服务机器人。顾客的"大脑"和"身体"通过 WebSocket 分开：身体可以是 2D 画面，也可以是项目内 `character/` 模块的 MuJoCo 3D 人物。
接口说明见 [docs/接口文档.md](接口文档.md)，小脑接口草案见 [docs/小脑接口.md](小脑接口.md)。

## 场景

场景信息不写在代码里，每个场景是 `scenarios/` 下的一个文件夹：

| 文件 | 内容 |
|---|---|
| `scene.json` | 地点（名字、2D 坐标 `pos2d`、3D 站位 `pose3d`）、物体、工作人员（职责、岗位、音色）、业务规定、给顾客/员工的补充说明、排队流程、障碍物、2D 装饰 |
| `personas.json` | 这个场景的顾客人设 |

现有场景：`bank`（银行营业厅，人设 wang / li / zhang）、`supermarket`（超市，人设 chen / zhou，目前只有 2D）。
顾客和员工的提示词、能用的地点和动作，都根据场景文件和身体声明的能力自动生成。
**新增场景只需要新建一个文件夹，不用改代码**；要在 3D 里用，还需要写 `pose3d` 和 `obstacles3d`，并在 3D 场景里摆好模型。

## 运行

```bash
pip install -r requirements.txt
copy .env.example .env      # 然后在 .env 里填 GLM_API_KEY

python main.py --persona wang               # 手动：你打字扮演服务机器人
python main.py --persona wang --mode auto   # 自动：AI 扮演机器人和柜员，你在旁边看
python main.py --scenario supermarket --persona chen --mode auto   # 换成超市场景
```

`--scenario` 默认 `bank`；`--persona` 默认取场景里的第一个人设。

默认模型 `glm-5.3` 强制开启思考，配置为 `GLM_THINKING=enabled`、
`GLM_REASONING_EFFORT=low`（简短对话使用较低思考强度）。若出现 400 / 1210
“不支持关闭思考”，检查 `.env` 是否仍为 `GLM_THINKING=disabled`，改为
`enabled` 并重启程序。切换到不支持 `reasoning_effort` 的旧模型时，设置
`GLM_REASONING_EFFORT=`。

### 输入框

| 输入 | 手动模式 | 自动模式 |
|---|---|---|
| 直接打字 + 回车 | 机器人说话（走语音 → ASR） | 不可用 |
| `/员工key 文本` | 其他工作人员说话，如银行 `/teller`、超市 `/cashier`（顾客要在他的岗位前） | 可以插一句 |
| `/sys 文本` | 旁白，直接给顾客，不走语音 | 同左 |
| 空格（输入框为空时） | — | 暂停 / 继续 |

滚轮翻看右侧记录，Esc 退出。

### 语音

- 顾客、机器人、柜员说话都用 Edge-TTS 合成（免费，需要联网，建议戴耳机）。加 `--no-voice` 不播放顾客语音。
- 银行端说的话播完后，把音频发给大脑，由顾客的 ASR（SenseVoice，本地 CPU）听写。
  右侧会显示 `[顾客听到] ...`，和原文不同时标出 `≠ 原文`。加 `--no-asr` 则直接把文字交给顾客。
- Edge-TTS 报 403 时，先 `pip install -U edge-tts`。

ASR 模型（约 230MB）放在 `models/sensevoice/`，新电脑上需要重新下载：

```bash
mkdir models && cd models
curl -LO https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17.tar.bz2
tar xjf sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17.tar.bz2
mv sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17 sensevoice
```

只需要 `model.int8.onnx` 和 `tokens.txt`，另外那个约 900MB 的 `model.onnx` 可以删掉。

### 自动模式的费用

自动模式下顾客和员工都在调 GLM，一场大约几十次调用。为防止失控，员工最多说 60 次就停止
（`env/body_2d.py` 里的 `MAX_STAFF_TURNS`）。排队等叫号的时间由场景文件 `workflow.seconds_per_person` 控制，调小可以加快测试。
单次 GLM 调用超过 60 秒会报错（`.env` 里 `GLM_TIMEOUT` 可改），不会再整场卡住没有提示。

### 分开启动

```bash
python brain_server.py                  # 先启动大脑，默认 ws://localhost:8765
python body_2d.py --persona wang        # 再启动 2D 身体（另开一个终端），换场景加 --scenario
```

同门的人物模型接入时，只需要启动 `brain_server.py`，人物模型按接口文档连上来即可。

### 日志

`logs/` 下每场会生成两个 `.jsonl`（文件名带场景和人设）：`*_brain.jsonl`（大脑：收到的每个事件、每轮的观察、
决策、ASR 结果、耗时、会话结束时是否还在思考）和 `*_manual.jsonl` / `*_auto.jsonl`（2D 身体：谁说了什么、执行了什么）。

## 3D 银行物理行走与自动对话

这是一个完整仓库：人物源码、程序模型、编辑脚本、动作参考、测试和人物调试界面都在 `character/` 中，不需要旁边再放一个人物项目。
银行场景使用项目内的 MuJoCo 引擎、人体模型、蒙皮、伸手 IK、手指姿态、足底传感和真人动作参考；银行接入层组合这些组件，提供目标导航、转向步态和银行流程。
环境包含咨询台、服务机器人、柜台、等候座椅、取号机和 ATM，并加入静态碰撞体。
首次使用需要 Node.js 22.12+ 和 npm：在本项目根目录执行 `npm ci`，一次安装 Agent 场景和人物模块的全部 JavaScript 依赖。
Python 依赖仍用 `pip install -r requirements.txt` 安装，并按上文配置 `.env` 和 ASR 模型。启动时检查仓库内源码、依赖锁文件和模型内容，变化后自动重建，模型与脚本一起保存在生成目录 `web/bank/`。
Windows PowerShell 若阻止运行 `npm.ps1`，改用 `npm.cmd`。

在本项目目录打开两个终端，分别运行（每个终端一条）：

```bash
python brain_server.py
python body_3d.py
```

浏览器打开 http://127.0.0.1:8080 ，等待人物加载后点击「开始自动对话」。
机器人会主动迎接入口处的顾客；双方使用 `StaffAgent` / `CustomerBrain` 轮流对话并播放语音（和 2D 用的是同一套）。
页面在 hello 里声明自己能做的动作和能去的地点（没有 3 号柜台、不能坐下），大脑只会用这些。
员工说的话会连同语音一起发给大脑，由 ASR 听写（和 2D 一样）；不想用 ASR 时大脑加 `--no-asr`。
顾客可走到咨询台、取号机，取号后走到等候区，收到叫号后走到柜台。
界面显示实际位置、目标距离、步态阶段、号码和叫号柜台。服务机器人说话时屏幕亮起；顾客支持挥手、点头、摇头、转头和伸手。
顾客音频播放时，音量驱动人物张嘴，暂停、播完或结束会合嘴；这是音量驱动的面部动画，不是音素级口型同步。机器人语音不会驱动顾客嘴部。
「暂停」会暂停音频和人物物理，并停止发起下一轮；已开始的网络调用无法撤销，
其结果会暂存，点击「继续」后播放。「结束」断开会话，丢弃晚到的回答。
咨询完成、员工没有需要补充的话或达到 20 个员工轮次后停止。

选择「手动：我扮演机器人」仍可打字，例如「请抬一下右手，告诉我您要办理什么业务」。
若浏览器阻止自动播放，点击语音播放器或「跳过本句语音」。语音合成失败会按文字继续。
需要纯文字测试时，大脑加 `--no-asr --no-tts`。
正常自动模式会调用双方的 GLM，产生 API 费用。

`walk_to` 先在静态布局上规划绕障路径，再执行重心转移、抬脚落脚、转向和双脚站稳。
位置由 MuJoCo 积分得出；控制器只驱动关节执行器，不改写运行中的根部位置/速度，不给根部施加辅助外力。
当前采用保守的小步慢走，每步约 4 秒仿真时间；一次跨大厅移动可能需要数分钟仿真时间。
可以选择 4× / 8×，倍速增加物理步数，物理步长仍为 0.002 秒；电脑性能不足时达不到标称倍速。
到达要求位置误差小于 8 厘米，朝向误差小于约 7°，双脚承重且速度稳定；跌倒、路径不可达、超时均回报失败。

取号为环境业务逻辑：在取号机站稳并完成伸手动作后取得 `A001`；重复取号不会重复分配。
到达等候区站稳后累计等待 16 秒仿真时间，再广播叫号到场景文件 `workflow.service_places` 里第一个 3D 能走到的柜台（银行是 `counter_1`）。暂停会停止计时。
队列目前为单顾客演示，其他顾客仅用排队数量表示；没有纸张抓取、按钮接触、物理递证件和真实银行交易。
`wave`、`nod`、`shake_head` 是分段动作并回正；`take` / `hand_over` 使用同门 `ReachTask`，手掌到目标距离小于 2.5 厘米且关节稳定才算完成，默认目标随人物朝向旋转。它们仍是伸手示意，不代表证件或号码纸已完成物理抓取。`look_at robot/help_desk` 仍为左/右转头的简化映射。
行走时使用 CMU 07_01 的上身参考与同门的全身协调组件；可在「行走伴随动作」中关闭。腿部继续使用已接入的银行转向控制器，同门新直行步态和支撑力优化器尚未替换银行腿部控制，以免丢失转向能力。
当前验证范围是这个固定平地大厅；尚不支持动态避人、楼梯、坐下起立、跌倒恢复或麦克风输入。
若项目内存在 `character/artifacts/scanned-private/runtime/eric.glb`，默认加载本地真人扫描人物，可在画面左上切换程序人物；缺失时使用仓库自带的完整程序人物，无需扫描资产也能运行。用 `--no-scan` 禁用，或 `--scan-file "实际路径/eric.glb"` 指定。扫描文件只通过本地专用端点读取，不复制到 `web/`，不进入 Git；取得资产的说明和使用条款见 [扫描资产说明](../character/docs/scanned-avatar.md)。人设改变对话，尚不改变外观。
材料缺失等情节可能导致提前离开，不保证每个人设都会办理成功。
「本地动作检查」只在未连接时可用，不调用大模型。

双方对话、小动作反馈和音频完成信息记录到 `logs/*_brain.jsonl`。
小动作反馈本身不触发 LLM；行走/取号完成后发送 `action_done` 让顾客决策下一步。
等候时不反复调用员工模型；广播触发顾客继续行动。抵达柜台后使用 `teller_speech`。
结束后可重新选择顾客；每次连接创建新对话会话。人物和号码保留在场景中，要从入口重新开始请先点「重置场景」。
默认模型目录是 `character/public/`；如需测试另一套资产，可用 `python body_3d.py --human-dist "实际路径/public"` 覆盖，自选资产应与当前人物源码兼容。
8080 被占用时使用 `--port 8081`。银行运行无需单独构建人物的 React 调试界面。
生成的 `web/bank/` 已忽略，每次启动都会检查更新；`integration.json` 记录本次构建的内容指纹，缺失或损坏时重建。
修改 `scene/` 源码后执行 `npm run build:scene`，然后刷新浏览器。

验证（不调用付费模型）：

- `node --test tests/actions.test.mjs`：动作完成、拒绝和真实到达条件。
- `python -m unittest discover -s tests -p "test_*.py"`：场景文件、能力交集、员工岗位、员工轮次与去重。
- `node tests/browser_3d.cjs`、`node tests/browser_auto.cjs`：真实 WASM 小动作、音频轮流播放及暂停恢复；需 Chrome 和已构建的场景。测试直接托管本地文件，无需启动 HTTP 服务。
- `node tests/browser_flow.cjs`：用身体测试桩验证取号、叫号、柜员、失败反馈等消息顺序，不用于证明物理行走。
- `node tests/browser_walk.cjs`：浏览器里的真实物理行走、倍速与暂停测试。
- `node scripts/test_layout.mjs`：地点间寻路和停车偏差下的障碍物安全距离。
- `node scripts/probe_physics.mjs --route`：真实 MuJoCo 完整路线，检查关节限位、抬脚、身体高度、位置误差、无根部改写和无外部辅助力；运行较慢。结果写入 `logs/physical-route.json`。
- `node scripts/probe_physics.mjs --integration`：新版模型初始化、挥手/点头/摇头、伸手误差、手指控制、取消、真实转身后伸手。
- `node tests/browser_integration.cjs`：自动启动临时本地服务，检查扫描人物（资产存在时）、外观切换、语音音量驱动嘴部、暂停和断开；使用合成测试音，不调用 LLM。

同门代码进度的具体接入范围见 [docs/人物进度整合.md](人物进度整合.md)。

## 两人协作开发

双方克隆同一个仓库，在根目录运行 `npm ci`。同门主要修改 `character/` 内的模型、人物控制和调试界面；你主要修改 `agent/`、`voice/`、`scenarios/`、`scene/` 与 `web/`。接口或动作能力的变化共同联调，具体流程见 [协作开发](协作开发.md)。

从根目录执行 `npm run dev:character` 可打开人物独立调试界面；`npm run build:character` 构建它；`npm run test:character` 运行人物自身测试；`npm run typecheck` 检查人物模块与银行接入层。统一依赖由根目录 `package.json` 和 `package-lock.json` 管理。

## 源码结构

```
scenarios/<场景>/    场景文件 scene.json + 人设 personas.json
scenario.py          读取场景文件；计算"场景提供 ∩ 身体能做"的能力；生成提示词里的场景部分
protocol.py          大脑和身体之间的消息格式、通用动作库（和场景无关）
brain_server.py      顾客大脑服务（WebSocket 服务端）：ASR → GLM → TTS
staff_auto.py        3D（浏览器）自动对话里的员工轮次
body_2d.py           单独启动 2D 身体
body_3d.py           托管 3D 页面与人物资产
main.py              一键启动：大脑 + 2D 身体
llm.py               GLM 调用的公共部分（带超时）
config.py            读取 .env
agent/brain.py       顾客大脑：观察 → GLM → {thought, speech, action, target, goal_status}
agent/staff.py       员工 Agent（场景里的全部工作人员，陪练用，不是测试对象），2D、3D 共用
agent/personas.py    读取场景里的人设
env/body_2d.py       2D 身体（WebSocket 客户端）：画面、执行动作、回报事件、员工说话
env/world.py         2D 环境状态与规则：走路、坐下、取号、叫号、动作完成/失败
env/renderer.py      pygame 画面
scene/               3D 场景（Three.js）与人物物理接入，地点和障碍物读自 scenarios/bank/scene.json
character/           人物模型与控制完整模块（源码、模型资产、编辑脚本、调试界面、测试）
web/                 3D 对话控制界面、语音排队、动作反馈
voice/               语音合成与播放、语音识别（SenseVoice，CPU）、音频工具
docs/                接口文档、小脑接口草案、进度记录
```
