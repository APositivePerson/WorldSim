# 头部深度、高程地图与动态绕行

启动 `python body_3d.py`，打开页面的“行走障碍测试”，点击“开始低矮障碍绕行”。每次场景在通道内随机横向放置 20 厘米高的路障，人物目标仍为咨询台。无需移除障碍、无需大脑连接或 VLM API。界面显示高程格、重规划次数和触发来源。

导航不接收测试路障的位置表。仿真深度相机位于人物头部，覆盖水平 120°、垂直向下 60° 至向上 15°、最远 3 米的视野。当前原型按水平 3°、垂直 5° 采样，每条射线只返回最先看到表面的距离；导航拿不到物体名称、完整尺寸、隐藏表面或测试路障坐标。头部转动时，深度相机方向随头部方向变化。

观察以 0.25 仿真秒间隔更新。深度命中点量化为 10 厘米三维体素，再按地面格汇总最低点、最高点和观测点数，形成 2.5D 高程地图。量化后最高点超过 8 厘米且最低点低于 1.9 米的格子进入导航代价图。注意判断使用量化高度：5 厘米观测可能四舍五入为 10 厘米，因此不能仅凭物体名义高度认定它不会触发避障。离开视野的观测保留；新深度射线明确穿过旧体素后才清除。已有银行静态地图继续作为场景先验。

## 查看感知与重规划原因

点击“开始低矮障碍绕行”后，场景左下角自动展开“感知地图与重规划记录”；普通场景也可手动展开。红格是实际判障格，紫框是阻挡当前路段的格子，蓝线是当前或新路线，灰虚线是事件发生时的旧路线，黑点是人物。灰色家具来自已有静态地图。红黄虚线轮廓只表示测试路障初始位置，供人工对照，不输入感知或规划。

下拉列表可以回看某次发现受阻、重规划、无路可走或失败事件。每条事件记录仿真时间、人物位置、当时的地图、原始观测高度、量化高度、新旧路线和非地面接触。点击地图格子查看其高度；也可勾选43厘米身体安全范围。重规划额外余量最多12厘米，在起终点附近按可用空间收缩，避免把满足基础身体距离的站位误判为不可到达；真正不满足43厘米身体距离的起终点仍会拒绝规划。

当前重规划由深度地图判障或VLM怀疑后经地图确认触发，接触信息仅是当时的辅助证据，不代表碰撞触发了规划。历史保留最近80条事件，每次新导航重新开始记录；“导出导航记录”保存JSON，方便比较不同场景。观测不到或未保留格子不代表那里一定没有障碍。此次诊断功能保留原有量化和规划规则，没有新增跨越能力。

路线受阻后，人物完成减停，在站稳状态下根据高程地图重规划，再交给原步态控制器执行。原地转向阶段继续观察，朝向行走段后才触发受阻处理，避免只看到物体边缘就反复停步。规划额外保留步态摆动和深度量化余量。

如果没有可通过路线，则继续观察、每 2 仿真秒尝试规划；停步处理超过 120 仿真秒回报失败，由现有动作失败链路交给 Agent。单次任务最多 12 次成功重规划，避免无限反复。到达仍由位置、朝向、脚底支撑与速度共同判断，不能凭规划成功报到达。

“移除路障”只是可选的环境扰动：隐藏显示、禁用碰撞，不调用导航恢复接口。恢复依据后续深度观测和规划。测试默认关闭 VLM；打开 VLM 后，GLM-4.6V 可以提供“行李、人员、柜台、临时封路”等语义怀疑，但不能直接写入三维坐标或绕过高程地图的路线校验。几何位置来自深度，物体含义来自 VLM，步态控制仍由人物控制器负责。

当前限制：这是由 MuJoCo 碰撞几何生成的仿真深度，不是带噪声的真实 RGB-D 相机；当前只对箱体碰撞几何建立深度点，不覆盖网格人物、透明物体、坑洞和高速移动障碍。高程地图能保留高度与占用，但导航最终仍把它投影成平面代价区域，尚未实现跨越、下蹲或从悬空物体下方通过。未知空间暂按可通行探索，不是完整 SLAM 或安全认证导航。完全堵路时采用有限等待后失败，尚未完成主动扫视和由大脑切换目标的验收。

验证入口：`npm.cmd run test:obstacle` 检查不同位置的真实物理绕行；`npm.cmd run test:obstacle-browser` 检查界面到物理到达，要求无移除操作且无视觉 API 调用。`npm.cmd run test:local-navigation` 检查视野、遮挡、地图清除、路径安全、途中新增障碍与完全堵路。完整物理测试需要数分钟，倍速仍受机器性能限制。

设计借鉴工程方法库 M011 的多时间尺度控制与 M013 的有限恢复：慢模型不接管步态执行，重规划受次数和时间限制。这是项目实现选择，不代表文献或模型保证本项目的效果。

2026-10-23 的旧验证使用单高度平面测距，只覆盖普通高路障。2026-10-25 的头部深度验收结果：单元测试证明 20 厘米障碍进入高程图、高物体产生第一表面遮挡、障碍移除后旧体素被自由射线清除、完全堵路受到恢复预算限制。真实 MuJoCo 中，1.35 米普通路障和 0.20 米低矮路障都在不移除的情况下完成绕行并稳定到达；低矮路障重规划 1 次，耗时约 539 仿真秒。浏览器完整流程记录了 728 个占用体素、1 次重规划、0 次视觉 API 调用，最终位置误差约 0.008 米。

双障碍回归补充：红色20厘米、黄色5厘米，红色横向偏移分别为 -0.25 米与 +0.25 米，黄色位于红色左侧1.1米、前方0.25米。修复额外余量误封终点后，两组分别在760.26与772.24仿真秒完成到达，各成功重规划1次，位置误差均小于8厘米，红黄障碍接触次数均为0。验收覆盖完整物理行走而非仅生成路线；目标站位和原到达判定保持不变。`test:obstacle` 已包含两组双障碍回归。接触检查产生的WASM临时对象会及时释放，避免长时间测试累计内存。
