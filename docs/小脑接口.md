# 人物控制接口 v1：实现规范

状态：**规范已制定，代码待实现和验收**。本文替代 v0.1 讨论稿，不代表现有代码已经实现。类型定义见 [LowLevelApi.ts](LowLevelApi.ts)，人物侧的负责范围见 [人物侧开发职责](人物侧开发职责.md)。

## 1. 分工和边界

Agent 侧负责决策、语音、银行业务、地点转坐标、路径规划、技能顺序与结果反馈。人物侧负责模型、步态、转向、平衡、关节、伸手和物理完成判断。“小脑”指动作控制能力，不要求引入新的大模型。

人物控制器只接收坐标和技能，不接收 counter_1 等银行地点名。人物侧在 character/src/ 实现 LowLevelApi，场景通过 import 创建并传给调度器；调试页可暴露 window.lowLevel 指向同一实例。迁移完成后，场景调度不得直接读写 qpos/ctrl 或依赖内部关节名。

## 2. 第一版技能

| 技能 | 要求 | 行为 |
|---|---|---|
| step_to | 必须 | 接收世界坐标 x,y,yaw，走到下一路径点并站稳，不负责全局寻路 |
| turn_to | 必须 | 原地转向指定 yaw 并站稳 |
| stand_still | 必须 | 安全停止移动并站稳 |
| gesture | 必须 | wave/nod/shake_head/raise_hand，手臂手势默认右手 |
| rest_pose | 必须 | 上身恢复自然姿态 |
| reach | 必须 | 指定 hand 和世界坐标 point，实际手掌到位后保持 |
| look_at | 可选 | 朝向三维目标点，固定左右转头不能声明为此能力 |
| sit/stand_up | 预留 | 未实现时不声明，调用返回 unsupported |

gesture.hold 默认 0，表示在动作峰值保持的仿真秒数，随后回到自然姿态；挥手、点头和摇头要有真实往复动作。reach.hold 默认 1 秒，完成后保持目标姿态，收手用下一条 rest_pose。伸手完成不代表物体已经抓取或交付。

capabilities 必须只声明已实现且通过测试的技能、手势和手侧。hands 表示同时支持伸手和手臂手势的手侧，必须包含 right；left 可后续增加。

## 3. 坐标和时间

- 长度米，角度弧度，世界坐标 Z 向上；point 为 [x,y,z]。
- x,y 为骨盆根部的地面投影。yaw=0 面朝 −Y，从上往下看逆时针为正，π/2 面朝 +X；角差按最短角计算。
- 时间、保持、超时、结果保留期使用引擎仿真时间，暂停时不累计。
- 页面是唯一物理时钟。每步顺序：调度器读取上一步结果并发技能 → api.update(dt) → engine.step()。update 读取上一步状态、检查结果并写本步控制量，结果最多延后一物理步。
- 禁止两个控制器同时写同一人物的腿部控制量；禁止用瞬移、重写运行中的 qpos/qvel 冒充完成。

## 4. 命令规则

第一版为**全身串行执行**，最多一个 running 技能。legs/arms/head 仅标记主要部位，不代表支持并发；reach 可以协调躯干和头部。

1. id 是实例生命周期内唯一的非空字符串。先验证参数、能力和身体状态；拒绝新命令不能影响旧命令，也不生成运行记录。
2. 接受新命令时，旧任务变为 interrupted/replaced，新任务变为 running。制动和姿态过渡计入新任务时间；无法安全替换时返回 busy，旧任务继续。
3. start 返回 accepted:true 后，status(id) 立即可查。接受不等于完成。
4. cancel(id) 将运行任务标为 interrupted/cancelled，并启动安全停止，不能继续追逐旧目标。取消不代表已经站稳，需要时调用 stand_still。取消未知或终态 ID 无副作用。
5. completed/failed/interrupted 是不可变终态。终态至少保留 60 仿真秒，清理后 status 返回 null，但旧 ID 不可复用；重建实例开始新生命周期。
6. onStatus 同步通知每次状态变化，包括 running；通知时 status 已更新。监听者异常不能破坏控制循环。监听者在下一调度步发新命令，避免回调重入。
7. body/status/capabilities 返回快照，外部修改不能影响控制器。

拒绝或失败原因：unsupported（不支持）、invalid_argument（非法参数）、duplicate_id（重复 ID）、busy（无法安全切换）、fallen（跌倒）、unreachable（不可达）、joint_limit（限位）、timeout（到期）、unstable（明确失稳）。运行失败要结束任务并安全停止。失败和中断必须带 reason、message。

## 5. 完成与超时

| 技能 | 默认完成标准 |
|---|---|
| step_to | 平面误差 < 0.08 m、朝向误差 < 0.12 rad，站稳持续 0.3 秒 |
| turn_to | 朝向误差 < 0.12 rad，站稳持续 0.3 秒 |
| stand_still | 根部平移速度 < 0.04 m/s、双脚支撑力各 > 10 N、骨盆高度 ≥ 0.65 m，持续 0.3 秒 |
| gesture/rest_pose | 最后一段完成，相关关节误差 < 0.14 rad、速度 < 0.12 rad/s，持续 0.2 秒 |
| reach | 实际手掌距离目标 < 0.025 m、相关关节速度 < 0.12 rad/s，保持指定 hold 时间；hold=0 仍需稳定 0.2 秒 |
| 可选 look_at | 头部前向与目标方向夹角 < 0.12 rad，稳定 0.2 秒；不要求眼球追踪 |

上身技能完成也要求站稳且未跌倒。骨盆高度 < 0.65 m 判为跌倒。body().settled 表示物理站稳，不表示处于目标位置。

所有坐标和角度必须有限；tolerance 和 timeout 必须有限且 > 0，hold 必须有限且 ≥ 0。tolerance 只覆盖位置/朝向容差。
未传 timeout：上身技能默认 35 秒（含保持），turn_to/stand_still 默认 240 秒，step_to 默认“平面距离 / walkSpeed × 3 + 240”秒。walkSpeed 使用实测保守速度，必须有限且 > 0。同一步先检查完成，再检查到期。

阈值是 v1 基线；模型变化确需调整时，同一提交更新规范、类型、调用方和测试，并说明实测原因，不能仅放宽阈值让测试通过。

## 6. 兼容当前系统

目前银行使用 window.human.performAction/cancelAction/navigate/getState，人物独立页主要使用 executeAction；本规范的 LowLevelApi 尚未接入。

迁移时保留现有页面入口，在适配层调用新技能：

| 现有入口 | 适配要求 |
|---|---|
| navigate(地点名) | 场景查坐标并寻路，再逐段调用 step_to |
| performAction({id,action,target}) | 手势转 gesture，take/hand_over 转伸手序列；场景将地点或物体目标转为坐标 |
| getState().actionResult | 汇总整个原命令结果，不能把中间技能完成当作整个命令完成 |
| cancelAction/stopNavigation | 取消技能和待执行序列，保持原有反馈格式 |
| look_at robot/help_desk | 新三维注视未实现时保留原固定转头兼容行为，但不声明新 look_at 技能 |

适配层负责原命令 ID 与内部唯一技能 ID 的映射；原命令为数字时仍保留对外数字 ID。银行 hello.capabilities 根据场景和技能能力生成，不能直接把技能名作为 Agent 动作名发送。

保留 setFace(patch) 和银行 setSpeechLevel(0..1)。语音识别、合成和播放归 Agent/页面；音量驱动嘴部不占动作任务、不产生动作完成事件。顾客播放结束、暂停和机器人发言时仍需清零。人物侧只维护面部渲染支持。

## 7. 实施与变更

先实现类型契约和技能测试，再接人物独立调试页和银行适配层。验收覆盖拒绝不影响旧命令、重复 ID、替换、取消、超时、暂停、跌倒、状态保留、能力一致性，以及真实物理动作完成。

内部实现问题由对应模块负责人处理。接口变化优先兼容；确需改变签名或含义时，同步全部调用方、类型、文档和测试，并记录版本变化。未实现的能力如实记录，完成状态以验收结果为准。
