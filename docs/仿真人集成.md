# HumanSimulation 人物集成

银行项目内的 `character/` 已同步同目录 `HumanSimulation-main` 的公开源码与资产，成为独立可构建的 npm workspace。同步记录 `character/upstream-integration.json` 包含 161 个文件的 SHA-256；原 `HumanSimulation-main` 不需要与银行同时启动，也没有被修改。

## 使用

在 `bank_customer_sim-main` 内运行：

```bash
npm ci
python body_3d.py
```

打开 `http://127.0.0.1:8080`，银行场景加载新人物。只测试身体、导航、路障和手势无需 API Key。完整对话仍需安装 `requirements.txt`、在 `.env` 填写 GLM_API_KEY 并另行启动 `python brain_server.py`；没有 ASR 模型可使用 `--no-asr`。本次回归使用脚本化大脑，不调用付费模型。

左上角身体面板提供：

- 关节执行器对照：默认。保留原银行行走和转向行为。
- 踝部肌肉：10 个双侧踝部肌肉单元，关闭相应 4 个原位置电机。
- 全腿肌肉：34 个功能肌群，关闭相应 14 个原位置电机。
- 肌梭反射：延迟 Ia/II 与拮抗抑制，可独立关闭对照。
- 物理眼球：每眼六条肌肉施力、真实眼球刚体运动，可独立关闭对照。

身体驱动只能在站稳且没有正在执行的手势/伸手时切换。暂停冻结物理和感觉队列。未经人体标定的工程参数仍是默认值，没有自动采用未通过验收的标定候选。

`npm run dev:character` 启动新版独立人物调试页，包含自然行走、感觉受限、头眼稳定、神经肌肉和人体标定等上游实验入口。银行导航通过固定朝向的局部坐标系复用上游 `NaturalWalking` 连续步态。默认关节执行器模式恢复 0.5 m/s，与上游自由行走默认值一致；踝部/全腿肌肉模式及超过 75 kg 的身体按上游限制使用 0.25 m/s。页面的“参考行走速度”和 `window.human.setWalkingSpeed(value)` 调整步速，`setSpeed(1|4|8)` 仍只调整仿真倍速。

站稳且方向对齐时直接启动原版连续步态，不再先插入旧式重心转移。转弯后先确认身体、关节速度和双脚位置/朝向收敛，再启动；大于 35 cm 的路段可用连续步态，短路段自动限制加速，按摆腿剩余时间与制动距离停步。发生明显重心跟踪误差、倾斜或失去双脚支撑时临时降低参考速度，恢复后再加速；界面显示“平衡调整减速”，`motion.balanceSlowdown` 提供状态。转向和精细落脚使用重心速度、加速度及角速度参考，只有足底确认承重后才完成一步，并把后续支撑参考锁定到实测落点和足部朝向。导航在家具旁收紧参考落点容差；最终 8 cm 到达验收与 43 cm 障碍净距不变。

局部转换只修改临时物理状态，真实身体仍由关节力矩驱动。临时状态只计算控制需要的运动学、质量矩阵和重力/速度偏置，不重复执行碰撞、执行器和约束计算；`npm run test:scratch-dynamics` 逐项比较所需结果与完整前向计算。银行大厅阴影贴图使用 1024 分辨率，减少额外渲染开销。步态复用上游落脚时序和载荷学习器，状态通过 `locomotion.walkingLearning` 提供；银行尚未接入完整感觉状态估计，这也不是完整生理小脑模型。

银行仿真时钟与上游 `SimulationLoop` 使用同样的 100 ms 每帧追赶上限，避免旧版 50 ms 截断在低帧率下额外减慢人物。`getState().timing` 提供丢弃的仿真时间和实际运行倍率。`npm run test:clock` 比较两套时钟；`HUMAN_SOURCE='<原项目目录>' npm run test:upstream-speed` 核对上游控制源码和模型，另行记录文档等差异，并比较同模型、0.5 m/s、14 秒直行距离；`npm run test:short-gait` 验证短路段能停稳并满足到达容差，记录包括制动和落脚确认的总时间，不能把这段总时间当作稳态步速。

扫描人物的眼窝位置来自 GLB 的绑定姿态；物理眼球提供转动，不能用程序人物的标准眼球位置覆盖扫描眼窝。此适配保留在 `scene/BankHumanRenderer.ts`，不修改同步的上游人物模块。`node scripts/test_bank_eyes.mjs` 验证程序人物，设置 `SCAN_FILE` 可同时验证本地扫描人物；`node scripts/test_bank_gait.mjs` 验证多个朝向及腿部驱动的自然行走和实际到达。

## 控制与数据路径

大脑 WebSocket → 银行 ActionRunner → Navigator / BankController → 银行步行参考与上肢动作 → 上游腿部肌肉 / 物理眼球 → 同一个 MuJoCoEngine → 同一个 HumanRenderer。

银行仍持有目的地名称、路径规划、障碍地图、取号/叫号、语音口型和原命令 ID。人物代码只提供身体物理、肌肉/肌梭、眼球、伸手、蒙皮、动作和调试组件。

不会同时创建上游 HumanController 和 BankController 来控制同一个银行人物。银行 `Locomotion` 是唯一腿部参考来源；肌肉模块在最终平衡参考生成后，把选定位置执行器替换为实际拉力。上肢/躯干仍使用原银行任务与协调器。运行中不重写真实 qpos/qvel，不向根节点添加平衡辅助力；受推测试中的外力是明确的有限测试刺激。

银行加载 `human-neuromuscular.xml`，再加入原家具和路障碰撞体；起点仍由银行场景配置确定。人物来源坐标保持 X 左、−Y 前、Z 上，长度米、角度弧度。保留 `human-free.xml` 供原始模型对照。

长路线联调还修复了目标点量化边界问题：取号机表面在高程体素中可能把精确目标点判为阻挡，人物承重侧移又会反复触发停车。规划使用原始深度命中的水平范围，仍向外保留原有 8 cm 表面余量，高程显示与判障规则继续量化；不引入隐藏物体语义。`planDestination` 在原有 8 cm 到达要求内最多偏移 6 cm，优先选择有摆动余量的安全落点，仍对整条路径执行原来的 43 cm 障碍安全距离检查；实际完成仍按原目的地误差和朝向判断。整片目标区域被挡时继续返回不可达，不降低安全距离。

原 `executeAction`、`performAction`、`navigate`、`stopNavigation`、`takeTicket`、`drainEvents`、表情、口型及截图 API 保持兼容。新增：

```js
window.human.setLegDrive('ankle'); // 'servo' / 'ankle' / 'full'，返回是否接受
window.human.configureMuscleSenses({reflexes:false});
window.human.setEyeTarget([0,-1,1.65]); // 三维世界坐标，非法参数返回 false
window.human.getState().legMuscles; // 模式、肌力、肌腱、Ia/II、原电机出力
window.human.getState().physicalEyes; // 双眼角度、速度、六肌激活与力
```

上述新增 API 不是 `docs/LowLevelApi.ts` 中尚待实现的完整技能契约，不改变大脑协议版本。`take`/`hand_over` 仍按银行原流程完成取号或伸手，不因此变成任意物体的真实抓取交付。

## 后续同步

```bash
npm run sync:human
npm run check:human
npm run typecheck
npm run build:scene
npm run build:character
```

来源路径不在旁边时使用 `npm run sync:human -- --source /path/to/HumanSimulation-main`。同步器仅处理明确列出的源码、公开资产、文档和配置，不复制 node_modules、dist、原始下载缓存、私人扫描数据或 `.env`；银行的 `scene/`、`web/`、Agent 和场景配置不会被同步覆盖。已有同步记录时，若 `character/` 中有本地编辑，与来源冲突会停止并指出文件，避免覆盖本地工作。来源的删除不会自动删除目标文件。

银行构建记录人物来源摘要；源文件、模型或构建产物变化会使构建缓存失效。部署只需要银行项目自身的源码和 npm/Python 依赖。

## 验证

```bash
npm run test:human-bank
npm run test:human-bank-browser
npm run test:human-bank-arrival
npm run test:integration
npm run test:route
npm run test:local-navigation
npm run test:browser
python -m unittest discover -s tests -p 'test_*.py'
```

`test:human-bank` 对三种驱动运行真实站立、35 N/120 ms 侧推恢复、挥手、转头补偿、短程行走/转向、到达与站稳，并检查控制器未改写 qpos/qvel、选中原电机出力为零；结果保存在 `logs/human-bank-physics.json`。浏览器测试验证 34 个肌肉单元、反射/眼球开关、真实动作结果 ID、暂停，以及页面无运行错误，截图为 `logs/human-bank-integrated.png`。

`test:route` 使用新神经肌肉模型的默认关节驱动，检查咨询台 → 取号机 → 等候区 → 柜台及业务事件；不将三种驱动的短程通过解释为全腿肌肉已通过所有银行长路线。原浏览器回归验证 WebSocket 动作回执、自动对话、取号/叫号状态机、口型、暂停和本地资产服务。脚本化/模拟大脑回归不等于真实 GLM 服务已验证。
