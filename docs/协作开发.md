# 同一项目中的两人协作

人物模块与 Agent 现在都在本仓库，不使用子模块，也不需要另外克隆一个人物仓库。

## 安装与启动

克隆后在仓库根目录运行：

```powershell
npm ci
pip install -r requirements.txt
```

从 `.env.example` 创建自己的 `.env`，填入 GLM_API_KEY；不要提交个人配置。ASR 下载步骤见 [详细使用说明中的语音部分](使用说明.md#语音)。程序人物已经随仓库提供，私人扫描资产缺失时自动使用程序人物。

银行端分别启动 `python brain_server.py` 和 `python body_3d.py`，访问 http://127.0.0.1:8080 。人物独立调试界面用 `npm run dev:character` 启动。

## 修改范围

人物控制按 [接口 v1 实现规范](小脑接口.md) 和 [类型定义](LowLevelApi.ts) 开发。当前是已制定的目标规范，尚未完成代码接入；人物侧的负责范围和验收要求见 [人物侧开发职责](人物侧开发职责.md)。内部实现问题由对应模块负责人修复；接口变更须同步类型、调用方、文档和测试。

| 模块 | 主要负责人 | 内容 |
|---|---|---|
| `character/src/`、`character/public/models/` | 同门 | 人物模型、物理控制、皮肤与渲染、动作能力 |
| `character/scripts/`、`character/assets/`、`character/artifacts/` | 同门 | 人物资产制作工具、参考动作、可编辑源资产 |
| `character/tests/`、人物调试界面 | 同门 | 人物动作、抓杯、步态和外观自身回归 |
| `agent/`、`brain_server.py`、`voice/` | 你 | 人设、决策、通信、语音识别与合成 |
| `scenarios/`、`scene/`、`web/` | 你为主 | 场景业务、导航、人物接入、对话播放与动作反馈 |
| `docs/`、根依赖锁文件、联调测试 | 双方 | 接口约定、依赖变更和整体验证 |

`scene/physics/` 的银行步态仍是既有适配实现。修改人物关节、引擎或控制方式时，双方共同检查这一层，避免新人物与银行控制不兼容。

## 分支与合并

双方各自建立功能分支，例如 `character/turning`、`agent/action-recovery`，提交 PR 后由另一人查看影响范围。人物代码和 Agent 代码可以在同一个 PR 中配套更新；不要同时直接修改主分支。

人物接口变化写明动作名称、参数、完成标准、失败原因及需要修改的接入位置。大脑可用能力仍由身体在 hello 中声明，不应宣布尚未实现的能力。

依赖通过 npm workspace 统一安装，根目录 `package-lock.json` 是唯一锁文件。在 `character/package.json` 增改依赖后，在根目录运行 `npm install` 并一起提交锁文件。不提交 node_modules、缓存或构建产物。

## 验证

```powershell
npm run typecheck
npm run test:actions
npm run test:integration
npm run test:character
npm run test:browser
python -m unittest discover -s tests -p "test_*.py"
```

银行路线或腿部控制有变化时，再运行 `npm run test:route`（完整物理路线较慢）。根浏览器测试使用本机 Chrome；可先安装 Chrome，人物独立 Playwright 套件需要时按 `character/README.md` 安装浏览器。

## 提交资产

`character/public/models/` 包含可运行的程序模型；`character/artifacts/` 中的 GLB、OBJ、Blender 源文件与历史模型测试夹具一并保留。查看模型和参考动作的 LICENSE / NOTICE 后再使用和分发。

扫描人物 `character/artifacts/scanned-private/` 受独立使用条款约束，已忽略。当前电脑的运行时扫描文件已复制到该本地目录；其他合作者按 `character/docs/scanned-avatar.md` 自行取得并准备资产。缺少它不影响程序人物和银行 Agent 系统运行。
